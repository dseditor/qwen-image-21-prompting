# Qwen-Image 2.1 提示詞寫法

Qwen-Image 2.1 附了兩份官方 **rewriter 系統提示**——一份給文生圖、一份給改圖。
它們原本是寫給一顆改寫模型用的。當流程裡沒有那顆模型時，**你就是那顆 rewriter**：
把對應的那份整份讀完，逐步照做。

```
沒有輸入圖  →  official_rewriter_t2i.txt   → {rewritten_prompt, wh_ratio}
有輸入圖    →  official_rewriter_edit.txt  → 再多一個 ratio_follow
```

t2i 規範是**八個依序的步驟，後面的步驟不准回頭改前面的決定**。
憑印象寫等於把八步壓成一步，而那正是它在防的事。

## 兩份規範的方向完全相反

**t2i —— 你是一個觀察者，在描述一張已完成的圖。**
現在式、第三人稱、直述句。約二十句、四百到五百字。
八到十四個方位詞，而且要**碰到角落**，不能全擠在中間。
光線要有自己一句。收束**只准一句**。畫面裡沒有要被閱讀的文字時，整個文字步驟跳過。

> 三個字的需求和三百個字的需求，產出**一樣長**。
> 需求短代表你要發明的部分更多，不是可以寫少一點。

**edit —— 你是在指揮一個手上拿著輸入圖的人。**
動詞開頭，不要描述「完成後的畫面」。

- **屬性解耦，而且要做滿。** 只改被點名的，改到明顯看得出來，其餘維持輸入原樣。
  兩種對稱的失敗：**洩漏**（動到沒被點名的東西）與**改太輕**（成品會被誤認成原圖）。
- **保留鎖的是內容，不是強度。** 辨識度靠「說清楚什麼不變」買到，不是靠把效果收斂。
- **說什麼不變，但不要重新描述它。** 沒被點名的東西只講類型、位置、角色。
  保留描述在模型讀來就是生成指令——**你把想保留的東西描述得越具體，它越會跑掉**。
- **身分要指向參考圖，不要用文字描述五官。** 文字描述會讓模型重新生成那張臉而失真。
- 多圖輸入一律用 `<image1>`、`<image2>`；單圖輸入一律不加標記。
  每張都要說明角色——誰是畫布、誰提供素材。

### edit 提示詞的自檢

**我要求保留的每一項，它的「成因」是不是也被我改掉了？**

同時要求「窗外改成下雨的夜晚」和「打光維持原樣」在物理上互相矛盾——
那道輪廓光本來就是你剛剛移除的白晝給的。模型會靜靜地選一邊，
而它沒有義務選你想要的那一邊。

## 規範層 vs 平台層

`wh_ratio` 與 `ratio_follow` 是**託管平台在讀的欄位**。
官方那張對照表（名片 9:5、A4 5:7、手機全面屏 18:39⋯）存在的目的是讓**你**挑比例，
模型不會讀它。

```
絕對不要把解析度、像素數、「4K」「名片」寫進 rewritten_prompt。
```

在本地後端（ComfyUI 之類）輸出尺寸來自你配置的 latent，
所以除非你自己的腳本去讀那些欄位，否則它們完全沒有作用。

> **採用別人的規範時，先切出跟他們平台耦合的那一半。**

## 三條來自實測的規則

**視角要用語意詞，不要用角度數字。**
`seen from directly behind` 有效；`rotated 180 degrees` 無效——
二十四幀的轉身序列每一幀都是正面，誤差與宣稱的角度**零相關**。

**帶條件圖時指令沒有反應，先換 seed，不要先改提示詞。**
受控診斷裡，同一組指令換一顆 seed 後四個方位全部正確；
而失效的那顆 seed 恰好是生成錨圖時用的那顆。

**你寫下的任何數量都會被當成配額執行。**
要求「三到五個要點」卻只提供兩個，缺口會從訓練分佈裡補滿——變成亂碼。
把每一個文字元素逐條列出，再加一條鎖：**清單以外不得出現任何文字**。
官方規範從另一面講了同一件事：**承諾不出來的字，就不要放進去。**

## 透明圖

```
開頭  This is an RGBA image with transparency.
結尾  The image has alpha channel and the background is transparent.
```

對一般物件很乾淨（實測全透明 59.2%、半透明僅 0.5%）。
**不適用於文字**——字形品質明顯下降，請見 `text-generation.zh-Hant.md`。
