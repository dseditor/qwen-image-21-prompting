# Qwen-Image 2.1 的文字生成

## 一句话版本

1. **在提示词里限定文字的最小尺寸。** 低于阈值，字形就会塌。
2. **出现乱码就换词重抽——同一个种子、换一种说法。** 这是唯一划算的技巧。
3. **必须由人看过。** 模型、LLM、OCR、VLM 都验不了字形。

这份文件其余内容，都是这三条背后的细节。

## 文字的最小尺寸

社区测试的共识：

```
简体中文   墨迹至少 20 px
繁体中文   50 px 以上
```

在提示词里用**占画面的比例**来写，不要写像素——模型不知道你的输出分辨率。
「约占画面宽度的八成」是可执行的，「50px」不是。

## 固定种子，换词重抽

失败是**系统性的，不是随机的**：坏掉的字符串会跨种子、跨叙述语言、跨字体风格一致地复现。
拿同一个字符串反复重抽是浪费时间。

```
生成 → 人看一眼 → 只替换坏掉的那个词 → 重新生成
```

**不要重写整行。** 一个坏词只需要换一个词。
实测「處理中」九次全错；「作業中」「進行中」「執行中」「運作中」全部一次就对。
代价是一个词，不是重新设计版面。

对外提供服务时，该说的只有一句：

> **如果有任何文字出现乱码或异常，告诉我，我帮你替换词汇重新生成。**

## 哪些因素【不影响】字形正确性

以下都是带对照组测过的：

| 维度 | 结果 |
|---|---|
| 叙述语言（繁体／简体／英文） | 无影响，产出一致。繁简提示词造成的像素差，只有换一个种子的 **18.9%** |
| 字体风格 | 同一个词跑粗黑体、立体招牌、霓虹灯管、毛笔书法、花字、卡通字——**六种全部正确** |
| 字号（超过阈值之后） | 无影响 |

**所以风险只在那串字本身。** 一个词只要验过一次，就能跨风格、跨语言、跨尺寸重复使用——
这也让「已验证字符串清单」值得维护。

## 繁体中文是比较不可靠，不是「一定会错」

这是个常见的夸大。受控测试中，四个高频且繁简有别的词
（開發／學習／體育／鐵路）全部正确，只有含「處」的字符串失败。

```
✓  繁体确实比简体不可靠，这是可确认的事实
✗  「繁体一定失败」
```

失败时它替换成一个**看起来合理的近邻**，而不是产生噪声——
「處」变成「虛」（共用虍部），在其他报告里则变成日文新字体「処」。
**跨种子一致的替换，是系统性牵引的特征，不是渲染抖动。**

## 🚨 字形你验不了，必须由人来验

这是这份文件里最重要的一条，而且很容易在不自觉的情况下违反。

```
用眼睛看        看到部首就假设是那个字      → 错
OCR / VLM       用上下文推断，读成本来的词   → 错
像素相似度       把错字评得比对的字还高      → 错
识字的人         「这个字错了」              → 对
```

**错误来源和检验者是同一个东西：上下文先验。**
任何依赖上下文消解歧义的读者，对这种错误都是**结构性失明**，
而且把尺磨细没有用——尺和被测的东西共用同一个失败模式。

据此分流：

| 这段文字 | 怎么做 |
|---|---|
| 必须正确（标识、标题、产品名、教材） | 用真实字体合成上去，或改用文字能力更强的模型 |
| 只是氛围（远处招牌、背景文字） | 让模型生成，接受偶尔出错 |
| 介于两者之间 | 生成后**请人看一眼**，并且明说你没有验证过 |

诚实面对这件事比另一条路便宜：
**一套切字、缩放、合成的精密管线，比直接换一个文字能力好的工具还慢。**

## 数量就是配额

写下数量就是开出空位，而空位不管你有没有给内容都会被填满。
十二行没指定内容的标签，回来就是十二行乱码。
把每一个该出现的字符串逐条列出，再明确锁死：清单以外不得渲染任何文字。

## 透明图帮不了文字

RGBA 输出对一般物体很干净，但要求透明会让字形质量下降。
把文字描述成「模切贴纸」可以修好 alpha 蒙版，但字形仍然比不透明版差。
