# Qwen-Image 2.1 提示词写法

Qwen-Image 2.1 附带两份官方 **rewriter 系统提示**——一份给文生图、一份给图像编辑。
它们本来是写给一个改写模型用的。当流程里没有那个模型时，**你就是那个 rewriter**：
把对应的那份整份读完，逐步照做。

```
没有输入图  →  official_rewriter_t2i.txt   → {rewritten_prompt, wh_ratio}
有输入图    →  official_rewriter_edit.txt  → 再多一个 ratio_follow
```

t2i 规范是**八个有序步骤，后面的步骤不得回头修改前面的决定**。
凭印象写等于把八步压成一步，而那正是它要防的事。

## 两份规范的方向完全相反

**t2i —— 你是一个观察者，在描述一张已完成的图。**
现在时、第三人称、陈述句。约二十句、四百到五百字。
八到十四个方位短语，而且要**触及画面四角**，不能全挤在中间。
光照要单独占一句。收束**只能有一句**。画面里没有需要被阅读的文字时，整个文字步骤跳过。

> 三个字的需求和三百个字的需求，产出**一样长**。
> 需求短意味着你要自己发明的部分更多，不是可以写少一点。

**edit —— 你是在指挥一个手里拿着输入图的人。**
以动词开头，不要描述「完成后的画面」。

- **属性解耦，而且要做满。** 只改被点名的，改到明显看得出来，其余保持输入原样。
  两种对称的失败：**泄漏**（动到没被点名的东西）与**改得太轻**（成品会被误认成原图）。
- **保留锁住的是内容，不是编辑强度。** 辨识度靠「说清楚什么不变」换来，不是靠把效果收敛。
- **说什么不变，但不要重新描述它。** 没被点名的内容只讲类型、位置、作用。
  保留描述在模型读来就是生成指令——**你把想保留的东西描述得越具体，它越会漂移**。
- **身份要指向参考图，不要用文字描述五官。** 文字描述会让模型重新生成那张脸而失真。
- 多图输入一律用 `<image1>`、`<image2>`；单图输入一律不加标记。
  每张都要说明作用——哪张是画布、哪张提供素材。

### edit 提示词的自检

**我要求保留的每一项，它的「成因」是不是也被我改掉了？**

同时要求「窗外改成下雨的夜晚」和「光照保持原样」在物理上自相矛盾——
那道轮廓光本来就来自你刚刚移除的日光。模型会默默选一边，
而它没有义务选你想要的那一边。

## 规范层 vs 平台层

`wh_ratio` 与 `ratio_follow` 是**托管平台读取的字段**。
官方那张对照表（名片 9:5、A4 5:7、手机全面屏 18:39⋯）存在的意义是让**你**挑比例，
模型不会读它。

```
绝对不要把分辨率、像素数、「4K」「名片」写进 rewritten_prompt。
```

在本地后端（ComfyUI 之类）输出尺寸来自你分配的 latent，
所以除非你自己的脚本去读那些字段，否则它们完全不起作用。

> **采用别人的规范时，先切出与他们平台耦合的那一半。**

## 三条来自实测的规则

**视角要用语义词，不要用角度数字。**
`seen from directly behind` 有效；`rotated 180 degrees` 无效——
二十四帧的转身序列每一帧都是正面，误差与所述角度**零相关**。

**带条件图时指令没有响应，先换种子，不要先改提示词。**
受控诊断中，同一组指令换一个种子后四个方位全部正确；
而失效的那个种子恰好是生成锚定图时用的那个。

**你写下的任何数量都会被当成配额执行。**
要求「三到五个要点」却只提供两个，缺口会从训练分布里补满——变成乱码。
把每一个文字元素逐条列出，再加一条锁：**清单以外不得出现任何文字**。
官方规范从另一面讲了同一件事：**承诺不出来的字，就不要放进去。**

## 透明图

```
开头  This is an RGBA image with transparency.
结尾  The image has alpha channel and the background is transparent.
```

对一般物体很干净（实测全透明 59.2%、半透明仅 0.5%）。
**不适用于文字**——字形质量明显下降，见 `text-generation.zh-Hans.md`。
