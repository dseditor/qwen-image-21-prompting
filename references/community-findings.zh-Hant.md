# Qwen-Image 2.1 —— 哪些真的做得到

宣稱的能力，實測過的。
這份文件存在的理由是：README 和大多數社群貼文都在講模型**能**做什麼，
而真正昂貴的知識是它**不能**。

每一條都寫了量測方法，方便你在自己的環境重驗。

---

## ❌ 360° 全景圖 —— 接縫不閉合

要求產生無縫的等距柱狀環境貼圖，得到的是**看起來像全景**、
但左右邊緣接不起來的寬圖。

**方法**：最左與最右各 8 像素條帶的平均絕對差，
對照組是同一張圖裡隨機取兩條 8 像素條帶。閉合的接縫應該接近 0。

```
seed A   接縫 32.99   隨機基線 48.62
seed B   接縫 40.07   隨機基線 48.56
```

另一份獨立報告量到 33.71，基線 70.53。兩邊結論一致：
**接縫只比兩條不相干的欄位稍微像一點而已。**

**可以用在**：寬幅場景、背景板。
**不能用在**：VR 環境貼圖，或任何需要繞一圈接回來的用途。

## ⚠️ 逐幀旋轉當影片 —— 只能當關鍵幀

一幀一張地生成轉身序列是可行的，但有前提：

- **角度數字帶不動它。** 用 `rotated N degrees clockwise` 跑二十四幀，
  每一幀都是正面，與首幀的誤差和宣稱角度**零相關**。
- **語意視角詞有效。** `seen from directly behind` 產生了正確的八方位轉身，
  鏡像視角之間對稱性極好（12.32 對 12.36）。
- **轉速不均** —— 名義上 22.5° 的一步會**吸附到最近的語意檔位**，
  而且幀與幀之間有輕微的縮放與位移漂移。
- **自回歸串接會退化。** 把第 i−1 幀當作第 i 幀的條件圖，大約六幀之後就卡住；
  背景亮度掉 42%、銳度升 163%，因為每一幀都經過 VAE，損失會疊加。

**把它當成關鍵幀產生器。** 中間幀交給插幀工具或影片模型。

## ✅／❌ 透明圖 —— 物件可以，文字不行

```
一般物件    全透明 59.2%、半透明 0.5%   → 遮罩乾淨、輪廓精準
文字當文字   alpha 幾乎是反的、字形全崩
文字當貼紙   alpha 正確了，但字形品質仍然下降
```

注意：**即使沒有要求透明，存出來的 PNG 也可能是 RGBA**——只是 alpha 全不透明。
**要判斷透明有沒有生效，看 alpha 的分佈，不要看檔案的 mode。**

## ✅ 文字生成 —— 見 `text-generation.zh-Hant.md`

摘要：最小字級有門檻；失敗是**逐字串的系統性失敗**而非隨機；
敘述語言與字體風格無影響；而且**沒有任何自動化檢驗者能驗字形正確性**。

## 📊 效能特性

來自一份獨立評測（單張 RTX 4090 48GB、bf16、diffusers）。
**絕對數字換到不同精度或不同框架就不成立，但關係的形狀會成立。**

| 性質 | 發現 |
|---|---|
| 步數成本 | 嚴格線性。24~30 步是實用區間；40 步相對 24 步幾乎沒有增益 |
| 解析度成本 | 耗時約為像素的 1.18 次方 |
| `true_cfg_scale` > 1 | 精確的 2 倍成本——它會再跑一次完整前向。預設值是 1.0 |
| 批次 | 沒有規模效益：1／2／4 張是 10.9／22.2／44.2 秒 |
| 決定性 | 同一顆 seed 位元級可重現 |
| KV cache | 快取的是「文字＋條件圖」前綴。純文生圖只快約 2%。每張條件圖多約 2 GB；**四張以內開，超過就關** |
| VAE 分塊 | 預設 tile 偏小；加大 tile 並保留重疊，多花約 1% 時間、省下約 8 GB |
