# Qwen-Image 2.1 —— 哪些真的做得到

宣称的能力，实测过的。
这份文件存在的理由是：README 和大多数社区帖子都在讲模型**能**做什么，
而真正昂贵的知识是它**不能**。

每一条都写了测量方法，方便你在自己的环境复验。

---

## ❌ 360° 全景图 —— 接缝不闭合

要求生成无缝的等距柱状环境贴图，得到的是**看起来像全景**、
但左右边缘接不上的宽图。

**方法**：最左与最右各 8 像素条带的平均绝对差，
对照组是同一张图里随机取的两条 8 像素条带。闭合的接缝应当接近 0。

```
seed A   接缝 32.99   随机基线 48.62
seed B   接缝 40.07   随机基线 48.56
```

另一份独立报告测得 33.71，基线 70.53。两边结论一致：
**接缝只比两条不相干的列稍微像一点而已。**

**可以用于**：宽幅场景、背景板。
**不能用于**：VR 环境贴图，或任何需要绕一圈接回来的用途。

## ⚠️ 逐帧旋转当视频 —— 只能当关键帧

一帧一张地生成转身序列是可行的，但有前提：

- **角度数字带不动它。** 用 `rotated N degrees clockwise` 跑二十四帧，
  每一帧都是正面，与首帧的误差和所述角度**零相关**。
- **语义视角词有效。** `seen from directly behind` 生成了正确的八方位转身，
  镜像视角之间对称性极好（12.32 对 12.36）。
- **转速不均** —— 名义上 22.5° 的一步会**吸附到最近的语义档位**，
  而且帧与帧之间有轻微的缩放与位移漂移。
- **自回归串接会退化。** 把第 i−1 帧当作第 i 帧的条件图，大约六帧之后就卡住；
  背景亮度降 42%、锐度升 163%，因为每一帧都经过 VAE，损失会叠加。

**把它当成关键帧生成器。** 中间帧交给插帧工具或视频模型。

## ✅／❌ 透明图 —— 物体可以，文字不行

```
一般物体    全透明 59.2%、半透明 0.5%   → 蒙版干净、轮廓精准
文字当文字   alpha 几乎是反的、字形全崩
文字当贴纸   alpha 正确了，但字形质量仍然下降
```

注意：**即使没有要求透明，保存出的 PNG 也可能是 RGBA**——只是 alpha 全不透明。
**要判断透明是否生效，看 alpha 的分布，不要看文件的 mode。**

## ✅ 文字生成 —— 见 `text-generation.zh-Hans.md`

摘要：最小字号有阈值；失败是**逐字符串的系统性失败**而非随机；
叙述语言与字体风格无影响；而且**没有任何自动化检验者能验证字形正确性**。

## 📊 性能特征

来自一份独立评测（单张 RTX 4090 48GB、bf16、diffusers）。
**绝对数字换到不同精度或不同框架就不成立，但关系的形状会成立。**

| 性质 | 发现 |
|---|---|
| 步数成本 | 严格线性。24~30 步是实用区间；40 步相对 24 步几乎没有增益 |
| 分辨率成本 | 耗时约为像素的 1.18 次方 |
| `true_cfg_scale` > 1 | 精确的 2 倍成本——它会再跑一次完整前向。默认值是 1.0 |
| 批量 | 没有规模效益：1／2／4 张是 10.9／22.2／44.2 秒 |
| 确定性 | 同一个种子位级可复现 |
| KV cache | 缓存的是「文本＋条件图」前缀。纯文生图只快约 2%。每张条件图多约 2 GB；**四张以内开启，超过就关闭** |
| VAE 分块 | 默认 tile 偏小；加大 tile 并保留重叠，多花约 1% 时间、省下约 8 GB |
