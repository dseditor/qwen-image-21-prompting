# Qwen-Image 2.1 的文字生成

## 一句話版本

1. **在提示詞裡限定文字的最小尺寸。** 低於門檻，字形就會塌。
2. **出現亂碼就換詞重抽——同一顆 seed、換一個說法。** 這是唯一划算的技巧。
3. **必須由人看過。** 模型、LLM、OCR、VLM 都驗不了字形。

這份文件其餘的內容，都是這三條背後的細節。

## 文字的最小尺寸

社群測試的共識：

```
簡體中文   墨跡至少 20 px
繁體中文   50 px 以上
```

在提示詞裡用**佔畫面的比例**來寫，不要寫像素——模型不知道你的輸出解析度。
「約佔畫面寬度的八成」是可執行的，「50px」不是。

## 固定種子，換詞重抽

失敗是**系統性的，不是隨機的**：壞掉的字串會跨 seed、跨敘述語言、跨字體風格一致地重現。
拿同一個字串一直重抽是浪費時間。

```
生成 → 人看一眼 → 只換掉壞掉的那個詞 → 重新生成
```

**不要重寫整行。** 一個壞詞只需要換一個詞。
實測「處理中」九次全錯；「作業中」「進行中」「執行中」「運作中」全部一次就對。
代價是一個詞，不是重新設計版面。

對外服務時，該說的只有一句：

> **如果有任何文字出現亂碼或異常，跟我說，我幫你替換詞彙重新生成。**

## 哪些因素【不影響】字形正確性

以下都是帶對照組量過的：

| 維度 | 結果 |
|---|---|
| 敘述語言（繁體／簡體／英文） | 無影響，產出一致。繁簡提示詞造成的像素差，只有換一顆 seed 的 **18.9%** |
| 字體風格 | 同一個詞跑粗黑體、立體招牌、霓虹燈管、毛筆書法、花字、卡通字——**六種全部正確** |
| 字級（過門檻之後） | 無影響 |

**所以風險只在那串字本身。** 一個詞只要驗過一次，就能跨風格、跨語言、跨尺寸重複使用——
這也讓「已驗證字串清單」值得維護。

## 繁體中文是比較不可靠，不是「一定會錯」

這是個常見的誇大。受控測試裡，四個高頻且繁簡有別的詞
（開發／學習／體育／鐵路）全部正確，只有含「處」的字串失敗。

```
✓  繁體確實比簡體不可靠，這是可確認的事實
✗  「繁體一定失敗」
```

失敗時它替換成一個**看起來合理的鄰居**，而不是產生雜訊——
「處」變成「虛」（共用虍部），在其他回報裡則變成日文新字體「処」。
**跨 seed 一致的替換，是系統性牽引的特徵，不是渲染抖動。**

## 🚨 字形你驗不了，必須由人來驗

這是這份文件裡最重要的一條，而且很容易在不自覺的情況下違反。

```
用眼睛看        看到部首就假設是那個字      → 錯
OCR / VLM       用上下文推斷，讀成本來的詞   → 錯
像素相似度       把錯字評得比對的字還高      → 錯
識字的人         「這個字錯了」              → 對
```

**錯誤來源和檢驗者是同一個東西：上下文先驗。**
任何靠上下文消解歧義的讀者，對這種錯誤都是**結構性失明**，
而且把尺磨細沒有用——尺跟被量的東西共用同一個失敗模式。

依此分流：

| 這段文字 | 怎麼做 |
|---|---|
| 必須正確（告示、標題、產品名、教材） | 用真字型合成上去，或改用文字能力更強的模型 |
| 只是氛圍（遠處招牌、背景文字） | 讓模型生，接受偶爾出錯 |
| 中間地帶 | 生完**請人看一眼**，並且明說你沒有驗過 |

誠實面對這件事比另一條路便宜：
**一套切字、縮放、合成的精密管線，比直接換一個文字能力好的工具還慢。**

## 數量就是配額

寫下數量就是開出空格，而空格不管你有沒有給內容都會被填滿。
十二列沒指定內容的標籤，回來就是十二列亂碼。
把每一個該出現的字串逐條列出，再明確鎖住：清單以外不得算繪任何文字。

## 透明圖幫不了文字

RGBA 輸出對一般物件很乾淨，但要求透明會讓字形品質下降。
把文字描述成「模切貼紙」可以修好 alpha 遮罩，但字形仍然比不透明版差。
